# An unreachable Search source is named, not silently dropped

`/search` fans out to all seven Bookstore clients plus Open Library, and both wrapper helpers used to catch `httpx.HTTPError` and contribute an empty list. That made a source that errored indistinguishable from one that genuinely found nothing: with Open Library intermittently unreachable from the development machine (7 failures in 10 consecutive calls, `ConnectTimeout`/`ConnectError`), a "Neuromancer" search collapsed from 15 Candidates to the 3 Delfi-only hits and rendered as though that were the complete answer. This is the Search-side counterpart of ADR 0005: "couldn't ask" is a distinct outcome from "asked, and it isn't there."

Each wrapped source now returns its name alongside its results, with `None` standing for failure, and the results page names every unreachable source. Two consequences are deliberate. When any source is unreachable the page no longer shows "No matches found" — that string is a claim about the catalogues, and unconsulted catalogues cannot support it, so a fully failed search shows only the unreachable notice. And a lone surviving match is shown as a Candidate rather than redirecting straight to its book page, because the Search that produced it was partial. Retrying, raising the request timeout, and caching Open Library responses were each considered and rejected for this change: they make the failure rarer without making it visible, and still fail silently once they run out of road. The underlying network flakiness is environmental and out of scope here; result caching remains separately planned.
